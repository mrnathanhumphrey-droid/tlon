## ⛔⛔ WHY EVERY RUN-0 LAG WAS UNSCOREABLE, NOT JUST THE EMPTY ONE

The null's `sd` is the spread of a MEAN over n pairs, so it falls like
`sigma/sqrt(n)`. A small cell yields a small z **whatever the speaker did** --
and the two axes read a small z in OPPOSITE directions:

```
lag 1    PASS is z >= 6.0   -> a tiny cell can NEVER pass -> fabricated
                               "perceive collapsed"
lag >=2  PASS is z <= 3.0   -> a tiny cell can NEVER fail -> vacuous
                               "release passed"
```

Together those spell §4.2 row **(d)** -- the verdict a degenerate speaker gets
for reasons of arithmetic. Measured on the re-read:

```
        n_pairs   sd       z        z_max(R=2)   threshold   reachable?
lag 1   5         0.5167   +0.915   2.464        6.0         NO
lag 2   3         0.6090   -0.446   2.291        3.0         NO
lag 3   1         0.9694   +0.253   1.284        3.0         NO
lag 4   0         --       --       --           3.0         NO (empty)
```

⭐ **Scoreability is now DERIVED, never picked** (`b16ed80`): a cell is readable
only if `resolving_power` -- the z of the MAXIMUM ATTAINABLE profile, same null,
same formula -- reaches the LOCKED `Z_LAG1_MIN`/`Z_LAGN_MAX` it is judged
against. ⛔ `n >= 20` would have been the freeze_procedure sin.

⭐⭐ **CONTAINMENT CHECKED AGAINST THE ARTIFACTS: no fired verdict moves.** From
