## 5 · The two defects that caused this

**A. A hardcoded batch size in the pipeline's `manifest` stage**
(`expected 6 adapters, manifest has 0`). The single-adapter gate run could never
have passed it. ⛔ The identical defect shape had been fixed in
`act2_retrain_orchestrate.py` ninety minutes earlier (`6 * 14` ->
`len(manifest) * SOLO_PER_BUILD`) and no sweep was done for siblings.

**B. ⛔⛔ TWO DOORS OUT, ONE GATE.** `may_terminate()` refuses while any artifact
is unpersisted — but it governs only the ORCHESTRATOR's terminate path. The
**watchdog terminates independently** over the Lambda API and has no concept of
unpersisted work. The entire s20620 remediation guarded one door and left the
other open.

⭐ **AND IT FIRES ON SUCCESS, NOT ONLY ON FAILURE.** A clean run writes `~/DONE`
and the watchdog terminates within one 300 s poll. The happy path had the same
five-minute window; it did not bite tonight only because the adapters were
pulled by hand ahead of it. `retrain12` succeeded and was terminated anyway,
taking all 84 solo transcripts with it.
