## D1 (SERIOUS) — `build_scene` never set a residue, so 13.0 was inert in the loop

13.0 built the residue at the grammar/metric layer and red-proofed it there. But
`build_scene`'s `node()` constructed `EventNode(root=…, orient=…)` and **never
read `pat.residue_any`**. Every generated scene was residue-free ⇒ `W_RESIDUE`
inert, `residue.normalized(None, None)` on the legacy 0.0 path, and **13.0's
landmine fix was not reached by a single run**.

It would not have crashed. A residue arm would have behaved exactly like a
no-residue arm and Part 2 would have read empty — the ledger's own fourth
misreport risk, arriving through the one door the ledger's red-proof does not
cover.

⭐ **Why every 13.0 test passed throughout:** they build Scenes **by hand**. A
test that hand-builds the object under test cannot certify the pipeline that
builds it in production. *Machinery correct ≠ machinery runs.* Found by
`tools/premise_13_2.py`, which asks the loop rather than the grammar.

**Fixed**, with the reproduction guard the fix needs: the residue draw is
**conditional on there being a choice to make**, so residue-free sets (archive,
v2, CR, TAO) consume **zero** extra rng values and phases 3–8 still reproduce
byte-identically. Asserted on **rng state**, not on output — the residue does not
render, so a surface comparison could not have seen the draw — and red-proofed
in the other direction (a multi-coordinate `residue_any` *must* draw).

**Banked as a standing rule:** any new residue-consuming path gets a
`build_scene`-level check, never a hand-built one.

## D3 — my own total-variation estimator was fake on first write

The premise check's "cluster-mates induce the same surface distribution" leg
re-seeded torch **and** the rng identically for both mates, so the two runs drew
the same channel sequence and TV came back **0.0000 by construction** — a
statistic that could not have come back positive. It also scored the raw
surface, which was 1,987 distinct strings in 2,000 draws and therefore estimated
nothing.

Fixed twice over: **independent seeds**, and a **dense statistic** (the
coda × aspect_reps joint, 20 cells). Now reads TV **0.0425** ⇒ Bayes ceiling
**52.1 %**, with a **red-proof** that plants a code and drives the same
statistic to **0.7985**. Recorded because it is the repo's own rule catching the
repo's own tool, inside the tool written to catch that class of error.

## D6 — table and head do not have equal parameter counts

Inherent to the manipulation: the head is a shared trunk (fixed size) and the
table is `n_refs × n_values` per channel; the categorical arm's 24-dim one-hot
input also makes its first trunk layer wider than the metric arm's 2-dim input.
Named as a confound rather than controlled, because equalising it would mean
crippling one parameterisation. ⭐ The **categorical×head vs categorical×table**
consistency check is what bounds it: one-hot into a linear layer is a row
lookup, so those two cells should agree despite the parameter-count difference.
If they do not, the parameter count is doing work and no metric cell is readable.

## D16 — the prereg's two anti-vacuity requirements were mutually exclusive

⛔⛔ **The single most important entry in this file.** PREREG `4ad552d4` §2
requires BOTH:

- **(a)** the head's trunk is an **MLP, not a linear map**, so the falsifying
  cell stays reachable — *"a linear trunk would have made the falsifier
  unreachable and the 2×2 self-confirming"*;
- **the consistency check**: *"one-hot into a linear layer is a row lookup, so
  categorical×head should land on categorical×table."*

**These cannot both hold.** The row-lookup equivalence is a property of a
**single** linear layer. With `Linear → Tanh → Linear → Tanh → Linear`, a
one-hot selects a row of the *first* matrix — a 32-dim **embedding** — and
everything above it is **shared across all 24 referents**. The depth that makes
(a) true is exactly what makes the consistency check false.

Both requirements went into the locked body, and I wrote both. The check fired
as designed (−30.60 pts, t −7.94) and stopped the metric cells being read, which
is the system working — but it fired on **my error**, not on a property of the
experiment.

## D19 — the consistency check was REPLACED, not repaired (Fix 2)

Proposal: `docs/PROPOSAL_13_2_CONSISTENCY_INVARIANT.md`. Implementation:
`tlon/harness/ceiling.py`, `tests/test_ceiling.py` (13 tests).
⛔ **Pending Nate's approval — the re-run does not fire until he rules.**

Old invariant: `categorical×head == categorical×table`. Invalid under the MLP
trunk (D16). **New invariant: the per-cell Bayes-ceiling gate** — from the
trained policy, compute exactly what a Bayes-optimal listener that knew the
policy would score inside each cluster; a cell is readable only if its headroom
over the 1/k floor exceeds the MDE.

**Two candidates were rejected, and the reasons are the record:**
- *"supervised head reaches 100 %"* — **disqualified by measurement.** That is
  Q1 from the diagnosis and it returned **100 % on both arms** in the very run
  where metric×head collapsed to 1/24. A gate that passes in the failure case it
  exists to catch is not a gate.
- *"head matches the table's diversity/accuracy"* — too strong, and it re-imports
  the equivalence assumption that just failed; it would re-block on a false
  failure whenever the head is merely good rather than table-equivalent.

⭐⭐ **The new gate closes Fix 1's named risk with the same arithmetic.** An
over-large entropy bonus produces a near-uniform policy, which has a *varied
argmax* — so a "count the distinct codes" statistic would call it healthy. The
ceiling cannot be fooled: uniform means every mate shares one distribution, the
max-sum is 1, and the ceiling falls to exactly the floor. Collapse and
over-entropy fail the gate for the same reason. That is why the sweep's
"restores diversity" criterion is written in **headroom**, never in code counts.

⛔ **Stated scope reduction:** the old check would have flagged "the head
systematically underperforms the table for an unknown reason". The new one will
not — it reports both as readable and lets the difference stand as a finding.
That is deliberate, and it is in the proposal for Nate to reject if he disagrees.
