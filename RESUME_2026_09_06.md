## ⏭ THE ONE OPEN THREAD — a named next step, not a decision

The full-weight arm's training loop produces a NaN model. **Six mechanisms are
excluded by positive test.** The fault is narrowed to:

> **A single tensor's gradient overflows in the BACKWARD at step 13, and
> `clip_grad_norm_`'s global norm spreads it to all 168 trainable tensors.**

**Next instrument:** `p.register_post_accumulate_grad_hook` — it fires as each
parameter's gradient is finalised, **before** clipping, so it names the one
originating tensor instead of the 168 casualties. Add at the same time (both
free): HF's own `grad_norm` from the logs (it is the *pre-clip* norm and should
read `inf`/`nan` at step 13, confirming this reading independently), and
per-tensor gradient absmax pre-clip so the growth across 11 → 12 → 13 is visible
on the actual culprit. One bounded run, ~$3.

⛔⛔ **NONE OF THIS IS ABOUT TLÖN.** D6's architectural floor is untouched. This
is a bug in machinery written on 2026-09-05/06, and the full-weight arm has
never produced a readable result because the loop has not yet run clean.

## ⛔⛔ THE CORRECTION THAT MATTERS MOST

**The founding symptom never happened.** `logging_nan_inf_filter` defaults to
`True`: when the loss is NaN or Inf, transformers **substitutes the running
average and logs that**. So the first run's "loss 7.548 → 0" was the filter, not
a collapse — the loss went NaN and the substituted average decayed toward zero.

Hours of hypotheses (degenerate objective, label path) were explaining a logging
artifact. **And the first version of the step trace inherited the same flaw** —
it read the loss from `on_log`, so its row 13 showed `loss=0.6404, finite=True`
while every gradient in the model was already gone. *The trace was showing the
mask.*

⭐ Fixed structurally: the raw loss is captured from the model output by
wrapping `compute_loss`, `logging_nan_inf_filter` is off while tracing, and the
framework's value is retained under the key **`loss_LOGGED_FILTERED`**. The
field name `loss` no longer exists in a trace row.

⭐⭐ **The rule to carry: a framework's logged or summarised value is a proxy;
the value the model returned is the arbiter, and the two diverge exactly when
something is wrong — which is precisely when anyone is looking.**

## What the evidence says now

| step | forward | backward | after optimizer |
|---|---|---|---|
| ≤ 12 | clean; activation absmax 8128 (`L3.mlp.down_proj`), stable | finite, clipped to exactly 1.0 | clean |
| **13** | **clean — RAW loss finite** | **one tensor overflows → global clip NaNs all 168** | 70 weights poisoned |
| 14 | NaN (a *consequence* of the NaN weights) | — | — |

Loss descended **4.4853 → 0.62 over twelve steps**. The model was training
normally with no precursor.

**Why exactly 70 weights and not 168:** every tensor below `min_8bit_size`
(4096) uses the 32-bit optimizer state path and takes the poisoned update; the
98 weight matrices use bitsandbytes' 8-bit blockwise path, which absorbs it. The
1-D/2-D split in the finished model describes **which optimizer state path
tolerates a NaN gradient**, NOT where the fault began. Four hypotheses were built
on that split as a localiser before the trace showed gradients broke on all 168.

## ⛔ SIX MECHANISMS EXCLUDED BY POSITIVE TEST

1. **8-bit quantisation of the 1-D params** — they never used 8-bit state;
   `min_8bit_size` is 4096 and every 1-D tensor here is 3584 or 512.
2. **Size-dependent NaN propagation** — one NaN gradient destroys 512, 3584 and
   8192 alike.
3. **Second-moment underflow** — 300 steps at gradient 1e-12, 1e-20 and exactly
   0 all stay finite.
4. **The label path** — 1297/2216 positions unmasked; `pad_token` (151643) ≠
   `eos` (151645). Corpus scan on the box: 20,002 rows, **0 zero-token, 0
   truncated**, lengths 55–317 against a 384 cap.
5. **The assembly at toy scale** — 16-cell ablation over mixed-dtype ×
   checkpointing × input-require-grads × autocast: no NaN anywhere, loss
   descends identically in all 12 runnable cells.
6. **Checkpointing × frozen stack, at real scale** — with gradient checkpointing
   OFF *and* `enable_input_require_grads()` not called, the failure is
   byte-identical: gradient non-finite at **step 13**, **168 tensors**, same
   first-tensor list.

⭐ **The determinism is the asset.** Two runs, different assemblies, identical to
the step. This is not a flaky failure being sampled — it is a fixed event, so the
instrument can be pointed rather than swept.

⚠️ **Do not reach for "bf16 overflow" by reflex.** bf16 has the *same exponent
range as fp32*; plain magnitude overflow is not the obvious mechanism and has
not been shown.
